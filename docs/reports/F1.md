# Laporan F1 - Fondasi Python yang Dapat Dijalankan

Status: `READY_FOR_REVIEW`
Tanggal: 16 September 2026

## Ringkasan

Fondasi Django dibangun dari nol: environment terpisah (Python 3.13.15 diinstal via winget,
sebelumnya tidak ada di lingkungan ini), dependency terkunci dengan hash, PostgreSQL 18.6 lewat
Docker Compose baru (bukan `compose.yaml` lama), custom user model dengan tiga role
(ADMIN/OPERATOR/VIEWER), penegakan akses server-side yang teruji otomatis, health check, lint
(ruff), test suite (Django test runner terhadap PostgreSQL nyata), dan CI workflow. Seluruh
exit gate F1 di `docs/phase-plan.md` dibuktikan lewat tes yang benar-benar dijalankan, termasuk
simulasi checkout bersih di direktori terpisah.

## Tes yang dijalankan (bukti acceptance, exit gate F1)

1. **Setup ulang dari checkout bersih berhasil.** Proyek disalin (tanpa `.venv`/`.env`) ke
   direktori terpisah; venv baru dibuat; `pip install --require-hashes -r requirements.txt
   -r requirements-dev.txt` berhasil (membuktikan lock file lengkap - awalnya gagal karena
   `setuptools`/`pip` tidak ter-hash, diperbaiki dengan `--allow-unsafe`, lihat "Masalah yang
   ditemukan" di bawah); `manage.py check`, `migrate`, `makemigrations --check --dry-run`, `ruff
   check`, `ruff format --check`, dan test suite (11/11) semuanya lulus di salinan tersebut.
   Salinan dihapus setelah tes. **LULUS.**
2. **Migrasi database berjalan** terhadap PostgreSQL sungguhan (bukan SQLite): `manage.py
   migrate` menerapkan 19 migrasi (contenttypes, auth, identity, admin, sessions) tanpa error ke
   container `gas-wayan-python-postgres-1`. **LULUS.**
3. **Role teruji otomatis.** 11 tes di `identity/tests.py` dan `health/tests.py`, dijalankan
   terhadap PostgreSQL nyata via `config.settings.test`: login benar/salah, dashboard untuk
   ketiga role, halaman khusus Admin dapat diakses Admin tapi **ditolak dengan HTTP 403** untuk
   Operator dan Viewer (server-side, lewat `PermissionDenied`, bukan UI yang disembunyikan),
   pengguna anonim diarahkan ke login (302) baik untuk dashboard maupun halaman admin-only, dan
   `createsuperuser` selalu memaksa role `ADMIN`. Semua **LULUS** (`Ran 11 tests ... OK`).
4. **Konfigurasi produksi tidak memakai `DEBUG=True` atau secret development.**
   `config.settings.prod` di-load tanpa `DJANGO_SECRET_KEY`/`DJANGO_ALLOWED_HOSTS`/`DATABASE_URL`
   di environment -> gagal dengan `ImproperlyConfigured` (tidak diam-diam jalan). Dengan ketiga
   env var disediakan, `settings.DEBUG` terverifikasi `False` (dan **tidak bisa** diubah jadi
   `True` lewat `.env` karena `prod.py` men-hardcode `DEBUG = False`, tidak membacanya dari env).
   Dibandingkan dengan `config.settings.dev` yang terverifikasi `DEBUG = True`. **LULUS.**
5. **Port tidak bentrok dengan proyek lama.** `docker-compose.yml` proyek ini memakai port host
   `55432` (bukan `5432`) dan nama compose project `gas-wayan-python` (bukan `gas-wayan`), setelah
   membaca `../Gas Wayan/compose.yaml` untuk memastikan tidak tumpang tindih. Image PostgreSQL
   18+ juga memerlukan perbaikan mount volume (lihat di bawah) yang kemungkinan besar berlaku
   juga untuk `compose.yaml` lama bila di-upgrade - dicatat sebagai temuan, bukan diperbaiki di
   proyek lama (di luar cakupan/izin). **LULUS** (untuk proyek ini).
6. **Admin dibuat lewat mekanisme aman.** Dibuktikan dengan `createsuperuser --noinput` (jalur
   non-interaktif untuk skrip/CI, password dari env var, tidak pernah hardcoded di kode) pada
   akun percobaan yang segera dihapus setelah diverifikasi `role=ADMIN`,
   `is_superuser=True`. Untuk pemakaian sehari-hari, `README.md` mengarahkan ke
   `createsuperuser` interaktif (prompt password, tidak pernah tersimpan di riwayat perintah).
   **LULUS.**
7. **Lint dan format bersih.** `ruff check .` -> `All checks passed!`; `ruff format --check .` ->
   seluruh file terformat. Dijalankan baik di working copy maupun di salinan checkout bersih.
   **LULUS.**

  test), tapi belum diverifikasi berjalan di runner GitHub Actions sungguhan.
- Tidak ada uji beban/performa (di luar cakupan F1, masuk F7).
- Tidak ada uji end-to-end browser (Selenium/Playwright) - demo manual di `docs/demo/F1.md`

- `openpyxl` dan pustaka bot Telegram belum diverifikasi/dipin - baru relevan F3/F6 (MIG-P07,
  MIG-P08 di `docs/migration-decisions-pending.md`).

## Masalah yang ditemukan dan diperbaiki selama F1 (dicatat, bukan disembunyikan)

1. **Docker image `postgres:18+` mengubah lokasi mount data.** Mount di
   `/var/lib/postgresql/data` (konvensi lama) membuat container crash-loop dengan pesan error
   eksplisit dari image resmi. Diperbaiki dengan mount di `/var/lib/postgresql` (konvensi baru
   untuk mendukung `pg_upgrade --link`). Lihat komentar di `docker-compose.yml`. **Catatan:**
   `../Gas Wayan/compose.yaml` (proyek lama) memakai mount lama yang sama dengan image
   `postgres:18.6-alpine` yang sama - berpotensi punya masalah serupa bila dijalankan, tapi ini
   di luar cakupan/izin untuk diperbaiki di proyek lama.
2. **`pip-compile --generate-hashes` tanpa `--allow-unsafe` menghasilkan lock file yang gagal
   diinstal dengan `--require-hashes`** karena `pip`/`setuptools` sengaja tidak ikut di-hash
   secara default. Diperbaiki dengan menambah `--allow-unsafe` di
   `scripts/compile_requirements.ps1` dan mengompilasi ulang kedua lock file. Diverifikasi lewat
   instalasi hash-verified yang berhasil di checkout bersih.
