## Ringkasan

Sumber (`../SERI TABUNG.xlsm`) diverifikasi ulang secara independen dari audit lama, memakai
parser OOXML read-only di PowerShell (tidak ada Python terinstal di lingkungan ini; VBA tidak
pernah dijalankan). Seluruh hitungan struktural inti (10.597 baris data, 540 baris kosong, 7.036

Perbedaan yang ditemukan (parser tanggal, split empty-count per kolom, kandidat duplikat bisnis)
didokumentasikan dan dijelaskan penyebabnya di `docs/source-audit.md`, bukan disembunyikan.

## Tes yang dijalankan (bukti acceptance)

1. **Checksum tidak berubah**: `SHA256(SERI TABUNG.xlsm)` = `D96FC4E7366BFC9B38CBD2BEB6985CAB3
   61BCA9E1D36CFAED5DD1FFDDFA33B81`, diverifikasi sebelum dan sesudah setiap run skrip - identik.
   LULUS.
2. **Deteksi perubahan sungguhan**: salinan di direktori scratch (bukan file asli) dimodifikasi
   satu byte -> checksum salinan berubah menjadi `5A2B4467...`, sementara checksum file asli
   tetap `D96FC4E7...`. Membuktikan skrip benar-benar mendeteksi perubahan, bukan selalu
   melaporkan "cocok" secara hardcoded. Salinan scratch dihapus setelah tes. LULUS.
3. **Idempotency**: skrip dijalankan dua kali berturut-turut terhadap file asli; output JSON
   identik kecuali field timestamp. LULUS.
4. **SearchData bukan transaksi**: `sheets.searchDataRowElements = 7` (termasuk header),
   `searchDataHidden = true` - jauh dari 10.597, sesuai `docs/migration-policy.md` A2. LULUS.
5. **Baris 10.599-10.601 tetap terdeteksi berisi data**: ketiganya `true` di
   `flaggedRows_10599_10601`, mengonfirmasi risiko VBA lama tetap relevan untuk F3. LULUS.

## Risiko dan blocker

- 3 keputusan arsitektur Python inti (MIG-P01 antrean worker, MIG-P02 tool dependency, MIG-P03
  versi persis) masih `PENDING`, harus dikunci di awal F1.
- 4 usulan kebijakan migrasi (gas kosong, kembali tanpa tanggal, konflik siklus, rekonsiliasi
  status - `docs/migration-policy.md` bagian B) menunggu keputusan pemilik sebelum F4; tidak
  memblokir F1-F3 karena F1-F2 adalah fondasi teknis dan F3 hanya membaca raw ke staging (belum
  publish).
- Parser tanggal reproduksi F0 lebih ketat dari audit lama (181 vs 38 tidak terparse pada
  Tanggal Pengiriman) - bukan bug ekstraksi (jumlah string non-kosong cocok persis), tapi perlu
  parser resmi dengan cakupan format yang disepakati di F3 (MIG-P06).
- Tidak ada Python terinstal di lingkungan kerja ini - F1 harus memilih dan memasang toolchain
  Python (terkait MIG-P02/MIG-P03); F0 sengaja menghindari instalasi software di luar cakupan
  fase ini dan memakai PowerShell yang sudah tersedia.
