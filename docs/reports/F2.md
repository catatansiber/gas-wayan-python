# Laporan F2 - Model dan Layanan Lifecycle

Status: `READY_FOR_REVIEW`
Tanggal: 16 September 2026

## Ringkasan

Tiga app baru (`catalog`, `operations`, `audit`) mengimplementasikan model domain dan layanan
bersama (dipakai calon web F5 maupun bot Telegram F6 tanpa duplikasi aturan bisnis) untuk tujuh
operasi: kirim, kembali, tukar, hilang, maintenance (start+complete), pensiun, dan
koreksi/reversal (pembatalan dispatch). Semua operasi: UUID primary key, penguncian baris
(`select_for_update`) dalam satu `transaction.atomic()`, idempotency payload-aware, audit log dan
outbox dalam transaksi yang sama, dan pemeriksaan role di level SERVICE (bukan cuma view) supaya
Telegram nanti otomatis tunduk pada aturan yang sama. 51 tes lulus terhadap PostgreSQL
sungguhan, termasuk tes concurrency berbasis thread nyata dan verifikasi manual bahwa dua
constraint database (CHECK dan partial unique index) benar-benar menolak data ilegal di level
SQL, bukan hanya di level Python.

## Model yang dibuat

| App | Model | Catatan |
| --- | --- | --- |
| `catalog` | `Customer`, `CustomerAlias`, `GasType`, `Cylinder` | `GasType.code` dibatasi 5 pilihan resmi (DEC-003); `Cylinder.serial_number` unique |
| `operations` | `Cycle` | Partial unique index `uniq_open_cycle_per_cylinder` (satu siklus aktif/tabung) + CHECK SQL manual `cycle_status_consistency_check` (migrasi 0002, ADR-P004) |
| `operations` | `LifecycleEvent` | Append-only; `reversed_event` self-FK untuk jejak koreksi |
| `operations` | `IdempotencyRecord` | Unique `(scope, actor, key)`; `payload_hash` untuk deteksi conflict |
| `audit` | `AuditLog` | `before`/`after` JSON, `reason`, `correlation_id`, generic `entity_type`/`entity_id` |
| `audit` | `OutboxEvent` | Diisi dalam transaksi yang sama; belum ada consumer (worker menyusul F6) |

## Layanan (`operations/services.py`)

| Fungsi | Role | Ringkasan |
| --- | --- | --- |
| `dispatch_cylinder` | ADMIN, OPERATOR | Buka Cycle baru, tabung AVAILABLE->OUT |
| `return_cylinder` | ADMIN, OPERATOR | Tutup Cycle aktif, tabung ->AVAILABLE |
| `exchange_cylinder` | ADMIN | Tutup Cycle lama (EXCHANGED) + buka Cycle baru untuk pelanggan sama, atomic, lock 2 tabung urutan deterministik |
| `mark_lost` | ADMIN | Tutup Cycle aktif jika ada (LOST), tabung ->LOST, alasan wajib |
| `start_maintenance` / `complete_maintenance` | ADMIN | AVAILABLE<->MAINTENANCE |
| `retire_cylinder` | ADMIN | AVAILABLE->RETIRED (terminal), alasan wajib, ditolak bila masih OUT |
| `reverse_dispatch` | ADMIN | Batalkan dispatch yang salah: tutup Cycle (REVERSED), tabung->AVAILABLE, event REVERSED menunjuk event DISPATCHED asli, alasan wajib |

**Keputusan role yang diambil (konsisten dengan tabel akses `requirements.md`/Panduan bagian 02,
bukan keputusan baru):** kirim & kembali = ADMIN+OPERATOR; tukar, hilang, maintenance, pensiun,
koreksi = ADMIN saja. Tabel lama secara eksplisit menyebut "OPERATOR: cari, kirim, kembali...
tidak boleh tukar/hilang/pensiun" - maintenance tidak disebut eksplisit tapi dikelompokkan
bersama transaksi khusus ADMIN di Panduan bagian 02, jadi diperlakukan sama (ADMIN-only).

**Cakupan reversal di F2 (sengaja dibatasi):** hanya membatalkan DISPATCH (kasus koreksi paling
umum: siklus baru dibuka keliru). Reversal untuk RETURNED/EXCHANGED/LOST belum ada - dicatat
sebagai pekerjaan lanjutan di `docs/migration-decisions-pending.md` (MIG-P09), bukan ditebak
implementasinya sekarang.

## Tes yang dijalankan (bukti acceptance, exit gate F2)

Semua dijalankan dengan `python manage.py test --settings=config.settings.test` terhadap
PostgreSQL 18.6 sungguhan (bukan SQLite). **51/51 lulus.**

1. **Hanya satu siklus aktif.** `ExchangeTests`, `ReturnTests`, dan verifikasi manual raw-SQL
   (lihat "Verifikasi tambahan" di bawah) membuktikan constraint `uniq_open_cycle_per_cylinder`
   menolak baris kedua bahkan lewat INSERT SQL langsung yang melewati Python sama sekali.
2. **Concurrency tidak menggandakan transaksi.**
   `ConcurrencyTests.test_two_concurrent_dispatches_only_one_succeeds` - dua thread nyata (koneksi
   DB terpisah) mencoba dispatch tabung yang sama bersamaan; tepat satu berhasil, satu ditolak
   `CylinderNotAvailable`, hanya satu `Cycle`/`LifecycleEvent` tercipta.
   `test_concurrent_retry_with_same_idempotency_key_yields_single_cycle` - dua thread dengan
   idempotency key SAMA -> keduanya melihat `Cycle` yang identik, bukan dua.
3. **Ulang key yang sama (retry).**
   `RetryIdempotencyTests.test_same_key_same_payload_replays_result_without_duplicating` - payload
   sama -> hasil lama dikembalikan, tidak ada `Cycle`/`LifecycleEvent`/`IdempotencyRecord` kedua.
   `test_same_key_different_payload_is_rejected` - payload beda dengan key sama -> `IdempotencyConflict`, tanpa efek samping.
4. **Return ganda.** `ReturnTests.test_double_return_without_new_dispatch_is_rejected` - return
   kedua (key BERBEDA, bukan retry) ditolak `NoActiveCycle` karena siklus sudah ditutup.
5. **Tukar gagal sebagian.**
   `ExchangeTests.test_exchange_partial_failure_rolls_back_completely` - tabung pengganti tidak
   ditemukan di tengah proses -> seluruh transaksi rollback; siklus lama TETAP `OPEN` dan tabung
   lama TETAP `OUT` (dibuktikan dengan query ulang setelah exception, bukan asumsi).
   `test_exchange_fails_when_replacement_not_available` - kasus tabung pengganti ada tapi sedang
   `OUT` - hasil sama (rollback penuh).
   `ExchangeConcurrencyTests.test_opposite_direction_exchanges_do_not_deadlock` - dua thread
   exchange bersamaan tidak deadlock (urutan lock deterministik berdasarkan serial_number
   terbukti bekerja, thread tidak hang sampai timeout 10 detik).
6. **Role ilegal.** `RoleEnforcementTests` (VIEWER ditolak dispatch/return; OPERATOR ditolak
   maintenance/retire) + tes role per operasi di `ExchangeTests`/`LostMaintenanceRetireTests`/
   `ReversalTests`. `test_no_action_is_taken_when_role_is_denied` membuktikan penolakan role
   tidak meninggalkan efek samping sama sekali (tidak ada Cycle/Event yang sempat terbuat).
7. **Reversal dan rollback.**
   `ReversalTests.test_reverse_dispatch_reopens_cylinder_and_leaves_trace` - setelah reversal,
   tabung kembali AVAILABLE, event `REVERSED` menunjuk event `DISPATCHED` asli lewat
   `reversed_event`, event `DISPATCHED` asli TIDAK terhapus (append-only, DEC-010), dan tabung
   bisa dikirim ulang secara normal setelahnya.

### Verifikasi tambahan (di luar test suite, dijalankan manual lewat `manage.py shell`)

Dua constraint database diverifikasi lewat INSERT SQL mentah yang sengaja melewati
`operations/services.py`, untuk membuktikan constraint itu nyata di level PostgreSQL (bukan
sekadar validasi Python yang bisa dilewati):

- `cycle_status_consistency_check` (CHECK): INSERT `Cycle` berstatus `OPEN` dengan
  `close_reason='RETURNED'` -> `IntegrityError ... violates check constraint`.
- `uniq_open_cycle_per_cylinder` (partial unique index): INSERT `Cycle` `OPEN` kedua untuk
  cylinder yang sudah punya satu `OPEN` -> `IntegrityError ... violates unique constraint`.

Data uji pada kedua verifikasi ini dihapus setelah pengujian (dikonfirmasi: 0 baris tersisa).

## Perbaikan yang dilakukan selama F2

- `pip-compile --generate-hashes` sebelumnya sudah diperbaiki dengan `--allow-unsafe` (F1); tidak
  ada dependency baru ditambahkan di F2 (semua model/service pakai Django inti).
- Ditemukan saat menulis migrasi help_text: perubahan `help_text` model dianggap perubahan skema
  oleh Django migration autodetector meski tidak berefek SQL - menghasilkan migrasi
  `0003_alter_cycle_data_quality_flag_and_more` yang murni no-op di level SQL tapi perlu tetap
  dibuat supaya `makemigrations --check` bersih.

## Risiko dan catatan untuk F3+

- MIG-P09 (baru): cakupan reversal terbatas pada DISPATCH - perlu keputusan desain lebih lanjut
  untuk reversal RETURNED/EXCHANGED/LOST sebelum F4 (impor mungkin butuh reversal kompleks saat
  membatalkan batch publish).
- `Cylinder.gas_type` TIDAK ada di model `catalog.Cylinder` - jenis gas melekat ke `Cycle`
  (`gas_type_at_dispatch`), bukan ke tabung, sesuai `docs/migration-policy.md` B1 (gas per siklus,
  bukan permanen ke tabung) dan `docs/column-mapping.md`.
- Django Admin untuk `Cylinder` mengizinkan Admin membuat/mengedit master tabung (field `status`
  read-only) - ini jalur pembuatan tabung baru sementara sebelum F5 punya form khusus.
