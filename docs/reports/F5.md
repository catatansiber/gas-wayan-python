# Laporan F5 - Layar Operasional Web

Status: `READY_FOR_REVIEW`
Tanggal: 16 September 2026

## Yang dibangun

- **Pencarian** (`/operasi/cari/`) - nomor tabung exact + filter nama pelanggan (icontains),
  pagination server-side (`django.core.paginator.Paginator`, 20/halaman). Status tabung dan
  kualitas data (`data_quality_flag` dari siklus terakhir) ditampilkan sebagai badge terpisah.
- **Detail/riwayat tabung** (`/operasi/tabung/<serial>/`) - status+kualitas data saat ini,
  siklus aktif (bila ada), riwayat siklus (kirim/kembali, terpaginasi), dan log kejadian
  lifecycle (terpaginasi terpisah) dengan waktu dirender di `Asia/Makassar`. Baris siklus yang
  `date_unknown=True` ditampilkan "tanggal tidak diketahui", terpisah dari yang punya tanggal
  pasti (exit gate: "laporan memisahkan tanggal diketahui dan tidak diketahui").
- **Log penggunaan tabung** (`/operasi/log/`) - daftar global `LifecycleEvent`, filter opsional
  per nomor tabung, pagination server-side (30/halaman).
- **Kirim/kembali** (`/operasi/kirim/`, `/operasi/kembali/`, role OPERATOR+ADMIN) dan **fungsi
  Admin** (`/operasi/admin/tukar|hilang|maintenance/mulai|maintenance/selesai|pensiun|koreksi/`,
  role ADMIN) - semuanya lewat pola generik **form -> preview -> konfirmasi**
  (`operations/views.py` `OperationSpec`/`_operation_view`):
  1. Form divalidasi (pesan error Bahasa Indonesia eksplisit di `operations/forms.py` - bukan
     mengandalkan terjemahan bawaan Django).
  2. Preview menampilkan ringkasan data yang akan disimpan + `idempotency_key` (UUID) dibuat
     SATU KALI dan disisipkan sebagai hidden field.
  3. Konfirmasi mem-POST ulang seluruh data + key yang sama ke `operations.services.*` -
     **double-click pada tombol "Konfirmasi" mengirim key+payload identik**, sehingga
     idempotency F2 mengembalikan hasil yang sama tanpa menggandakan transaksi.
  Semua mutasi lewat `operations.services` - TIDAK ADA `.save()` langsung pada `Cycle`/
  `Cylinder` di layer view (diverifikasi: `operations/views.py` tidak mengimpor apa pun yang
  memungkinkan itu, hanya memanggil fungsi service).
- **Role ditegakkan server-side** lewat `identity.permissions.role_required` per view (F1) -
  VIEWER hanya bisa GET pencarian/detail/log; OPERATOR+ADMIN bisa kirim/kembali; ADMIN saja
  untuk tukar/hilang/maintenance/pensiun/koreksi. 403 dari `PermissionDenied`, dirender lewat
  `templates/403.html` yang sudah ada sejak F1.
- **Responsif 360px-desktop** - `templates/base.html` dirombak: container lebar (960px desktop,
  menyempit penuh di layar sempit), tabel dibungkus `.table-wrap` (scroll horizontal bila
  perlu, bukan overflow merusak layout), form/input `width:100%`, navigasi `flex-wrap`, dan satu
  media query `max-width:480px` untuk preview list jadi satu kolom. Tidak ada JS - seluruhnya
  CSS murni + Django Templates server-rendered (ADR-P010).
- `catalog.Cylinder.latest_cycle` (properti Python read-only baru, TANPA migrasi) - membantu
  tampilan memisahkan status tabung dari kualitas data siklus terakhir tanpa query N+1 manual
  di template.

## Tes yang dijalankan

`python manage.py test operations.test_views --settings=config.settings.test` -> **21/21
lulus**, mencakup persis skenario yang diminta:

- **Role**: VIEWER baca-saja (search/detail/log 200, form mutasi 403 baik GET maupun POST
  langsung ke endpoint konfirmasi); OPERATOR tidak bisa buka form khusus Admin (403); ADMIN bisa
  semua; anonymous di-redirect ke login (302).
- **Alur normal**: `test_full_dispatch_then_return_flow` - cari tabung kosong, kirim (form ->
  preview -> konfirmasi), tabung jadi OUT dengan nama pelanggan tampil di detail, lalu kembali,
  tabung jadi AVAILABLE, riwayat menampilkan event RETURNED.
- **Input salah**: tanggal masa depan ditolak dengan pesan "tidak boleh di masa depan"; field
  kosong menampilkan "Wajib diisi."; alasan kosong pada aksi Admin ditolak; tukar ke tabung yang
  sama ditolak "tidak boleh sama"; kirim tabung yang masih OUT menampilkan pesan domain error
  F2 ("tidak dapat dikirim") tanpa transaksi baru.
- **Hasil kosong**: nomor tidak ditemukan -> "Tabung dengan nomor tersebut tidak ditemukan.";
  filter pelanggan tanpa hasil -> "Tidak ada hasil untuk pencarian ini."; query kosong tidak
  menampilkan listing lama (arsitektur server-rendered per-request, tidak ada state client-side
  yang bisa basi).
- **Timezone**: `LifecycleEvent.created_at` (UTC di database) dirender di halaman detail persis
  sama dengan `django.utils.timezone.localtime(...)` yang diverifikasi berselisih **+8 jam**
  dari UTC (`Asia/Makassar`/WITA) - dibuktikan lewat perbandingan string literal di HTML, bukan
  asumsi.
- **Idempotency double-click**: dua POST konfirmasi dengan `idempotency_key` identik -> tetap
  hanya 1 `Cycle` tersimpan.
- **Pagination server-side**: 25 tabung dibuat untuk satu pelanggan, halaman 1 = 20 hasil,
  halaman 2 = 5 hasil, tidak ada tumpang tindih antar halaman.

`python manage.py test --settings=config.settings.test` (seluruh proyek) -> **109/109 lulus**
(88 lama + 21 baru), tidak ada regresi. `ruff check .`/`ruff format --check .` bersih.
`makemigrations --check --dry-run` -> tidak ada drift (F5 tidak mengubah skema).

**Verifikasi tambahan lewat HTTP sungguhan** (bukan hanya Django test Client) - dev server
lokal (`manage.py runserver`) diakses lewat `curl` dengan sesi cookie nyata dan token CSRF
sungguhan: login -> cari (kosong, ditemukan, tidak ditemukan) -> form kirim -> preview -> submit
konfirmasi dua kali (double-click) -> detail tabung. Hasil: status HTTP dan isi HTML sesuai
ekspektasi di setiap langkah; setelah dua kali konfirmasi, `Cycle.objects.filter(...).count()`
tetap **1**. Data uji sintetis (`SMOKE-0001`, "Demo Smoke Pelanggan", user
`demo_smoke_operator`) sengaja **dibiarkan** di database dev sebagai jejak audit (AuditLog dan
IdempotencyRecord melindungi User terkait dari penghapusan lewat FK PROTECT - konsisten dengan
prinsip append-only F2), bukan data pelanggan asli.

## Yang TIDAK dijalankan / di luar scope F5

- Tidak ada tangkapan layar browser sungguhan (tidak ada alat screenshot di lingkungan kerja
  ini) - verifikasi memakai `curl` (HTTP request/response nyata terhadap dev server yang benar-
  benar berjalan) dan Django test Client (render template nyata). CSS responsif diverifikasi
  lewat pembacaan kode (media query, `.table-wrap`, unit relatif), bukan lewat rendering visual.
  Pemilik proyek disarankan membuka `docs/demo/F5.md` di browser sungguhan (termasuk resize ke
  360px) sebagai langkah verifikasi visual terakhir.
- Ekspor (CSV/dsb.) belum dibangun - phase-plan F5 menyebut "ekspor bila formatnya sudah
  disetujui"; format ekspor belum disetujui pemilik proyek (tidak ada di
  `docs/migration-decisions-pending.md` maupun instruksi sesi ini), jadi sengaja tidak dibangun
  daripada menebak format.
- Dashboard ringkas (statistik agregat) belum dibangun - instruksi sesi ini tidak menyebutnya
  secara eksplisit (fokus: cari, kirim/kembali, fungsi Admin, riwayat, log). Dicatat sebagai
  potensi pekerjaan lanjutan bila diminta.
- Pencarian pelanggan untuk form kirim memakai `<select>` sederhana (bukan autocomplete/live
  search) - jumlah `Customer` di database saat ini kecil (hasil publish F4 terbatas karena
  kebijakan migrasi masih PENDING). Perlu direvisit bila jumlah pelanggan bertambah signifikan
  pasca F4 lanjutan.

## Risiko dan item terbuka

- Bila jumlah `Customer` tumbuh besar (pasca konfirmasi kebijakan B1/B2/B3 dan publish lanjutan
  F4), `<select>` pelanggan di form kirim perlu diganti komponen pencarian - dicatat, bukan
  masalah mendesak untuk skala tes saat ini.
- Format tanggal input HTML5 (`type="date"`) mengikuti locale browser pengguna untuk
  tampilannya, tapi nilai yang dikirim ke server selalu ISO (`YYYY-MM-DD`) - tidak bergantung
  locale, jadi validasi tanggal tetap konsisten. Ditampilkan ke pengguna sebagai `DD/MM/YYYY`
  sesuai keputusan lama.
