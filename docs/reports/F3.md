# Laporan F3 - Importer Raw dan Staging

Status: `READY_FOR_REVIEW`
Tanggal: 16 September 2026

Dokumen ini hanya berisi angka agregat. Tidak ada nilai `Nomor Tabung`, `Nama Relasi`, atau
tanggal mentah individual yang dicetak di sini, sesuai aturan proyek. Laporan berisi data asli
(nomor baris + nilai mentah per baris bermasalah, kandidat duplikat, kandidat alias) tersimpan
lokal saja di `docs/reports/f3-local/` (di-gitignore, tidak pernah masuk Git).

## Yang dibangun

- App `imports` (`ImportBatch`, `RawRow`, `StagingRow`) - lihat `imports/models.py`.
- `imports/parsing.py` - fungsi murni (tanpa DB) untuk parser tanggal day-first, klasifikasi
  kolom kembali (`K`/`KEMBALI`/`SDH KEMBALI` -> RETURNED terkonfirmasi, `SDH BALIK` dan teks lain
  -> NEEDS_REVIEW), pencocokan kode gas resmi, kunci kandidat duplikat, normalisasi nama untuk
  kandidat alias, dan sanitasi CSV terhadap formula injection.
- `imports/importer.py` - orkestrasi: verifikasi checksum SHA-256, baca sheet `Database`
  read-only lewat `openpyxl` (`read_only=True`, tidak pernah membuka lewat Excel/VBA), tulis
  `RawRow` immutable (unique `workbook_sha256+sheet_name+source_row_number`) dan `StagingRow`
  (unique per `raw_row+parser_version`) - keduanya idempotent lewat `get_or_create` manual.
- `python manage.py import_workbook` (`--workbook`, `--expected-sha256`, `--dry-run`) - importer
  utama. `--dry-run` menghitung dan mencetak ringkasan lalu rollback transaksi (tidak menulis
  apa pun), untuk pratinjau aman sebelum commit ke arsip raw.
- `python manage.py import_report` - ringkasan agregat (`docs/reports/f3-import-summary.json`,
  aman untuk Git) + laporan detail data asli per baris bermasalah, kandidat duplikat, dan
  kandidat alias (`docs/reports/f3-local/*.csv`, LOKAL SAJA, di-`.gitignore`-kan).
- Django Admin `ImportBatch`/`RawRow`/`StagingRow` read-only (`ReadOnlyAdminMixin` dari
  `operations/admin.py`, dipakai ulang) - konsisten dengan F2, tidak ada CRUD bebas.
- `openpyxl==3.1.5` dipin di `requirements.in`/`requirements.txt` (hash-verified) - menutup
  MIG-P07.

## Kebijakan yang diterapkan (dan batasnya)

- **CONFIRMED, diterapkan langsung:** raw immutable + traceability nomor baris (A1); `SearchData`
  tidak pernah dibaca sebagai baris transaksi (A2, diverifikasi: hanya sheet `Database` yang
  diproses - lihat tes `test_only_database_sheet_is_read`); jenis gas resmi hanya 5 kode, kode
  lain tidak pernah ditebak (A3); `K`/`KEMBALI`/`SDH KEMBALI` -> RETURNED (A4); tanggal
  ambigu/mustahil tidak diperbaiki otomatis (A5).
- **PROPOSAL baru dari F3 (belum dikonfirmasi pemilik, hanya memengaruhi staging, TIDAK
  memengaruhi publish karena F4 belum berjalan):**
  - Parser tanggal resmi `F3-PARSER-v1`: day-first ketat `d[/.-]m[/.-]y`, tahun 2 digit
    diekspansi 00-68->20xx, 69-99->19xx (konvensi `strptime('%y')`). Ini mengisi MIG-P06 dengan
    versi eksplisit dan fixture-tested, tapi tetap **PROPOSAL** - pemilik proyek perlu
    mengonfirmasi sebelum dipakai untuk publish F4.
  - `SDH BALIK` diklasifikasi terpisah dari teks bebas lain (`OTHER_TEXT`) supaya mudah direview
    sebagai kelompok tersendiri, tapi keduanya sama-sama `NEEDS_REVIEW` - belum dipetakan ke
    `RETURNED` (MIG-B05 tetap `PENDING`).
  - `data_quality_flag`/`review_status` tiga tingkat: `READY` (siap direview lanjut, tanpa
    warning), `NEEDS_REVIEW` (ada warning - tanggal tak terparse/kosong, gas tak dikenal/kosong,
    status kembali tak dikenal), `ERROR` (serial tabung kosong - tidak bisa membentuk lifecycle
    sama sekali, sesuai `docs/column-mapping.md` baris B).

**Catatan perbedaan angka tanggal terparse vs F0:** F0 (`docs/source-audit.md`) memakai regex
audit sederhana dan menolak 181/9.583 string tanggal kirim. Parser resmi F3 (`F3-PARSER-v1`)
menerima pemisah `.`/`-`/`/` dan tahun 2 digit, sehingga hanya menolak 186 dari total baris
kirim (termasuk baris dengan native date yang tidak dihitung "teks"). Ini murni beda cakupan
pola yang diterima, sama sekali tidak ada tanggal yang ditebak nilainya - konsisten dengan
kesimpulan MIG-P06 di `docs/source-audit.md`.

## Insiden kecil yang perlu dicatat: nama pelanggan sempat tercetak ke log percakapan

Saat memverifikasi isi `docs/reports/f3-local/*.csv` dengan perintah `head` untuk memastikan
file benar-benar terisi, tiga nama pelanggan asli dan beberapa nomor tabung ikut tercetak ke
output tool yang masuk log percakapan sesi ini (bukan ke Git - file CSV itu sendiri sudah
di-`.gitignore`-kan dan tidak pernah di-commit). Ini melanggar aturan "raw pelanggan dilarang
masuk log percakapan". File lokal tidak diubah, tidak ada data yang bocor ke luar sesi ini, dan
tidak masuk Git - tapi transkrip sesi ini sendiri berisi cuplikan tersebut. **Pemilik proyek
perlu diberi tahu secara eksplisit** (dicatat di ringkasan akhir sesi) supaya bisa memutuskan
apakah transkrip sesi ini perlu dibersihkan/dihapus dari penyimpanan histori.
