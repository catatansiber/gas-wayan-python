# Demo F1 - Fondasi Python yang Dapat Dijalankan

Ikuti langkah ini untuk memverifikasi hasil F1. Jalankan dari root `gas-wayan-python/`.

## 1. Setup dari checkout bersih

Ikuti `README.md` bagian "Setup dari checkout bersih" langkah 1-6 (venv, install hash-verified,
`.env`, `docker compose up -d postgres`, `migrate`, `createsuperuser`).

**Expected:** setiap langkah selesai tanpa error. `pip install --require-hashes` berhasil (bukti
lock file lengkap - tidak ada paket tanpa hash). `migrate` menerapkan seluruh migrasi ke
PostgreSQL container baru (port `55432`), bukan SQLite.

## 2. Jalankan aplikasi dan login per role

```powershell
python manage.py runserver
```

Buka `http://127.0.0.1:8000/`. Tanpa login, akan diarahkan ke `/login/` (302, bukan 200 - buktikan
dengan DevTools Network tab atau `curl -I http://127.0.0.1:8000/`).

Buat tiga user lewat `python manage.py shell` untuk demo (atau lewat Django Admin
`/admin/identity/user/` setelah login sebagai Admin):

```python
from identity.models import User, Role

User.objects.create_user(username="demo_admin", password="Demo12345!", role=Role.ADMIN)
User.objects.create_user(username="demo_operator", password="Demo12345!", role=Role.OPERATOR)
User.objects.create_user(username="demo_viewer", password="Demo12345!", role=Role.VIEWER)
```

Login bergantian sebagai `demo_admin`, `demo_operator`, `demo_viewer` di `/login/`.

**Expected:** ketiganya berhasil login dan melihat dashboard dengan badge role masing-masing.

## 3. Buktikan penolakan akses server-side (bukan hanya UI)

Saat login sebagai `demo_operator` atau `demo_viewer`, buka `http://127.0.0.1:8000/admin-only/`.

**Expected:** halaman menampilkan "Akses ditolak" dengan status HTTP **403** (bukan halaman
admin-only yang sesungguhnya, dan bukan 404 - buktikan status code lewat DevTools atau:

```powershell
# ganti session cookie sesuai user yang sedang login di browser, atau uji via automated test
python manage.py test identity.tests.RoleAccessTests.test_operator_is_denied_admin_only_page_by_server -v 2
```

Saat login sebagai `demo_admin`, halaman yang sama harus tampil normal (200).

## 4. Health check publik

```powershell
curl http://127.0.0.1:8000/health/
```

**Expected:** `{"status": "ok", "database": "ok"}`, tanpa perlu login.

## 5. Jalankan seluruh tes otomatis

```powershell
python manage.py test --settings=config.settings.test
```

**Expected:** `Ran 11 tests ... OK`, database tes dibuat dan dihapus otomatis
(`test_gaswayan_dev`), berjalan di PostgreSQL nyata (lihat output `Creating test database`).

## 6. Lint dan format

```powershell
ruff check .
ruff format --check .
```

**Expected:** `All checks passed!` dan semua file sudah terformat.

## 7. Konfigurasi produksi tidak bisa "kebobolan" DEBUG=True

```powershell
$env:DJANGO_SETTINGS_MODULE = "config.settings.prod"
python -c "import django; django.setup()"
```

**Expected:** gagal dengan `ImproperlyConfigured: Set the DJANGO_SECRET_KEY environment
variable` (tanpa `DJANGO_SECRET_KEY`/`DJANGO_ALLOWED_HOSTS`/`DATABASE_URL` di environment, prod
settings menolak start - tidak diam-diam jalan dengan nilai development). Set ketiga variabel
tersebut lalu ulangi - kali ini berhasil, dan `settings.DEBUG` harus `False` (bisa dicek lewat
`python -c "...; from django.conf import settings; print(settings.DEBUG)"`).

Jangan lupa `$env:DJANGO_SETTINGS_MODULE = $null` (atau buka terminal baru) setelah selesai supaya
tidak mengganggu perintah `manage.py` berikutnya yang mengasumsikan `config.settings.dev`.

## 8. Port tidak bentrok dengan proyek lama

```powershell
docker compose ps
```

**Expected:** container `gas-wayan-python-postgres-1` di port host `55432`, compose project
`gas-wayan-python` - berbeda dari `gas-wayan-postgres-1` di port `5432`/project `gas-wayan` milik
`../Gas Wayan/compose.yaml` (tidak dijalankan oleh demo ini, hanya dibandingkan).

## Menghentikan aplikasi

`Ctrl+C` di terminal `runserver`, lalu `docker compose down` (tambahkan `-v` hanya jika sengaja
ingin menghapus data PostgreSQL lokal proyek ini).

## Coba kasus gagal (bagian dari acceptance)

- Login dengan password salah -> harus ditolak dengan pesan error, bukan diam-diam masuk.
- Akses `/` tanpa login -> redirect ke `/login/?next=/` (302), bukan menampilkan dashboard.
- `pip install -r requirements.txt` (tanpa `--require-hashes`) tetap berfungsi tapi TIDAK
  memverifikasi hash - gunakan selalu `--require-hashes` untuk instalasi yang diverifikasi.
