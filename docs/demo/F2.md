## 1. Kirim satu tabung; kembalikan; kirim lagi

```powershell
python manage.py shell
```

```python
from datetime import date
from catalog.models import Customer, Cylinder, GasType
from identity.models import Role, User
from operations import services

# Data sintetis - bukan data pelanggan asli
gas = GasType.objects.get_or_create(code="O2")[0]
customer = Customer.objects.create(display_name="Demo Pelanggan")
cylinder = Cylinder.objects.create(serial_number="DEMO-0001")
operator = User.objects.create_user(username="demo_operator", password="x", role=Role.OPERATOR)

cycle1 = services.dispatch_cylinder(
    actor=operator, serial_number="DEMO-0001", customer_id=customer.id,
    gas_type_code="O2", sent_at=date.today(), idempotency_key="demo-kirim-1",
)
print(cycle1.status, Cylinder.objects.get(serial_number="DEMO-0001").status)  # OPEN OUT

cycle1_closed = services.return_cylinder(
    actor=operator, serial_number="DEMO-0001", returned_at=date.today(),
    idempotency_key="demo-kembali-1",
)
print(cycle1_closed.status, Cylinder.objects.get(serial_number="DEMO-0001").status)  # CLOSED AVAILABLE

cycle2 = services.dispatch_cylinder(
    actor=operator, serial_number="DEMO-0001", customer_id=customer.id,
    gas_type_code="O2", sent_at=date.today(), idempotency_key="demo-kirim-2",
)
print(cycle2.status)  # OPEN - siklus baru, bukan siklus lama dibuka kembali
```

**Expected:** urutan status persis seperti komentar di atas.

## 3. Ulang key yang sama (retry idempotency)

```python
kwargs = dict(actor=operator, serial_number="DEMO-0001", customer_id=customer.id,
              gas_type_code="O2", sent_at=date.today(), idempotency_key="demo-retry")
services.dispatch_cylinder(**kwargs)
```

Panggil lagi (tabung sudah OUT dari sini, tapi karena key SAMA, tidak akan dicoba
eksekusi ulang, hasil lama dikembalikan):

```python
from operations.models import Cycle
before = Cycle.objects.count()
services.dispatch_cylinder(**kwargs)  # payload identik, key identik
after = Cycle.objects.count()
print(before == after)  # True - tidak ada Cycle baru
```

## 4. Tukar ke tabung yang tidak tersedia

```python
admin = User.objects.create_user(username="demo_admin", password="x", role=Role.ADMIN)
cylinder_busy = Cylinder.objects.create(serial_number="DEMO-0002")
services.dispatch_cylinder(actor=operator, serial_number="DEMO-0002", customer_id=customer.id,
                            gas_type_code="O2", sent_at=date.today(), idempotency_key="busy-1")

try:
    services.exchange_cylinder(actor=admin, old_serial_number="DEMO-0001",
                                new_serial_number="DEMO-0002", exchanged_at=date.today(),
                                idempotency_key="demo-exchange-fail")
except Exception as e:
    print(type(e).__name__, e)  # CylinderNotAvailable
```

**Expected:** `CylinderNotAvailable`, dan siklus DEMO-0001 tetap OPEN (tidak ada perubahan
separuh jalan):

```python
Cycle.objects.get(cylinder__serial_number="DEMO-0001", status="OPEN")  # tidak melempar error
```

## 6. Koreksi/reversal

```python
services.reverse_dispatch(actor=admin, serial_number="DEMO-0001",
                           reason="Demo koreksi", idempotency_key="demo-reverse-1")
print(Cylinder.objects.get(serial_number="DEMO-0001").status)  # AVAILABLE
```

Cek jejak di Django Admin (`/admin/operations/lifecycleevent/`, login sebagai admin) - event
`DISPATCHED` asli masih ada, plus event `REVERSED` baru yang menunjuknya. Coba klik salah satu
baris - form harus **read-only** (tidak ada tombol simpan), membuktikan "Admin tidak boleh
mengubah tabel event secara bebas melalui Django Admin".

## Coba kasus gagal tambahan (bagian dari acceptance)

- `services.return_cylinder(..., serial_number="DEMO-0001", ...)` dua kali dengan idempotency
  key **berbeda** setelah tabung sudah kembali -> `NoActiveCycle` pada panggilan kedua.
- `services.retire_cylinder(...)` pada tabung yang statusnya `OUT` -> `CylinderNotAvailable`
  ("kembalikan dulu").
- `services.mark_lost(..., reason="")` -> `DomainError` ("alasan wajib").
