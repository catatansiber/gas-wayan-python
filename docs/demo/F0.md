# Demo F0 - Audit dan Keputusan Bisnis

Ikuti langkah ini untuk memverifikasi hasil F0. Tidak ada aplikasi yang berjalan pada fase ini -
demo berupa pemeriksaan dokumen dan menjalankan ulang skrip audit read-only.

## 1. Verifikasi checksum sumber tidak berubah

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "..\SERI TABUNG.xlsm"
```

**Expected:** `D96FC4E7366BFC9B38CBD2BEB6985CAB361BCA9E1D36CFAED5DD1FFDDFA33B81`, sama dengan
yang tercatat di `docs/source-audit.md` dan `../Gas Wayan/docs/workbook-audit.md`.

## 2. Jalankan ulang audit read-only

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/audit_workbook.ps1 `
  -WorkbookPath "..\SERI TABUNG.xlsm" -OutFile "docs/reports/f0-audit-raw.json"
```

**Expected:**
- Perintah selesai tanpa error, mencetak `OK - hasil ditulis ke ...` dan checksum yang sama.
- `docs/reports/f0-audit-raw.json` terisi ulang dengan angka yang identik ke run sebelumnya
  (idempotent - lihat `docs/source-audit.md` untuk angka lengkap): 10.597 baris data, 540 baris
  kosong, 7.036 `Nomor` unik, 2.450 nomor tabung unik, 1.288 relasi unik (normalized).
- Checksum `SERI TABUNG.xlsm` **tidak berubah** setelah skrip dijalankan (bandingkan langkah 1
  sebelum dan sesudah) - membuktikan skrip benar-benar read-only.

## 3. Periksa SearchData tidak dihitung sebagai transaksi

Buka `docs/reports/f0-audit-raw.json`, cari `sheets.searchDataRowElements`.

**Expected:** nilai kecil (7, termasuk header) - jauh dari 10.597 - dan `searchDataHidden: true`.
Ini membuktikan cache pencarian VBA tidak ikut terhitung sebagai baris `Database`.

## 4. Baca dokumen keputusan

Buka berurutan: `docs/phase-plan.md` (bagian F0), `docs/decisions.md` (ADR-P001, penggantian
stack), `docs/column-mapping.md`, `docs/migration-policy.md` (bagian A vs B), dan
`docs/migration-decisions-pending.md`.

**Expected:** setiap keputusan berlabel jelas `CONFIRMED` (dari proyek lama) atau `PENDING`/
`USULAN` (baru, proyek Python). Tidak ada satu pun butir `PENDING` yang diam-diam ditulis seolah
final di dokumen lain.

## 5. Cek baris berisiko 10.599-10.601

Di `docs/reports/f0-audit-raw.json`, field `flaggedRows_10599_10601` harus berisi tiga entri
(`10599`, `10600`, `10601`) semuanya `true` - mengonfirmasi risiko VBA lama (baris ini berisi
data padahal `tbl_reset` VBA berhenti menampilkan daftar di baris 10.598) tetap berlaku dan wajib
ditangani di F3 (baca seluruh used range, bukan berhenti di `COUNTA`).

## Coba kasus gagal (bagian dari acceptance F0)

- Ubah sementara satu byte `SERI TABUNG.xlsm` di salinan lain (bukan file asli) dan jalankan
  skrip audit terhadap salinan itu -> checksum yang dicetak harus berbeda dari
  `D96FC4E7366BFC9B38CBD2BEB6985CAB361BCA9E1D36CFAED5DD1FFDDFA33B81`, membuktikan skrip memang
  mendeteksi perubahan, bukan selalu melaporkan "cocok".
- Jalankan skrip dua kali berturut-turut pada file asli -> kedua `docs/reports/f0-audit-raw.json`
  harus identik (idempotent, tidak ada efek samping akumulatif).
